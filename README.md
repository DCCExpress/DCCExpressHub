# DCCExpressHub

DCCExpressHub is an ESP32-based companion and web control hub for **DCC-EX** model railway command stations.

It provides a browser-based interface for locomotive control, layout operation, configuration, diagnostics and automation, while the actual DCC signal is still generated by the connected DCC-EX command station.

> **DCCExpressHub is not a command station.**
>
> It connects to a DCC-EX CommandStation / EX-CSB1 over the native DCC-EX TCP protocol and acts as the web, control and integration layer around it.

---

![DCCExpressHub screenshot](doc/images/Screenshot%202026-09-05%20110304.png)

## Architecture

```text
Browser
   │
   │ HTTP / WebSocket
   ▼
DCCExpressHub
ESP32 / M5Stack
   │
   │ DCC-EX native TCP protocol
   ▼
EX-CSB1 / DCC-EX CommandStation
   │
   │ DCC
   ▼
Model railway layout
```

The Hub keeps the browser UI, layout configuration, runtime state and DCC-EX connection in one small ESP32-based device.

DCC-EX remains responsible for:

- generating the DCC signal,
- locomotive packets,
- accessory commands,
- programming,
- track power,
- command-station feedback.

DCCExpressHub adds the user interface and higher-level layout functionality around it.

---

## Main features

Current functionality includes:

- locomotive control,
- locomotive editor,
- function control,
- browser-based layout editor,
- turnouts and accessories,
- signals and signal logic,
- occupancy / sensor integration,
- runtime layout operation,
- decoder programming,
- EX-CSB1 connection configuration,
- track power control,
- raw DCC-EX console,
- gamepad support,
- device configuration,
- LittleFS file browser,
- diagnostics and runtime status,
- complete Export / Import backup,
- browser-based firmware installation,
- browser-based serial recovery and configuration.

The browser UI is stored on the Hub itself in LittleFS and does not require a separate application during normal use.

# Installation

The recommended installation method is the browser-based DCCExpressHub Installer.

## Web Installer

Open:

```text
https://dccexpress.github.io/DCCExpressHubWeb/installer/
```

The installer uses ESP Web Tools and Web Serial directly from the browser.

No local Python, Node.js, PlatformIO or `esptool.py` installation is required for end users.

### Browser requirement

Use a desktop Chromium-based browser with Web Serial support, for example:

- Google Chrome
- Microsoft Edge

Connect the Hub to the computer using USB.

---

## USB serial driver

Before using the Web Installer, make sure the operating system detects the Hub as a serial / COM device.

Depending on the ESP32 or M5Stack board, a USB-to-serial driver may be required. Common USB-UART chips include:

- **CH340 / CH341**
- **Silicon Labs CP210x**

On Windows, first connect the board and check **Device Manager → Ports (COM & LPT)**.

If a COM port appears and the board is identified correctly, no manual driver installation is normally needed.

If no serial port appears, install the driver for the USB-UART chip used by your board.

For CP210x devices, use the official Silicon Labs VCP driver page:

```text
https://www.silabs.com/software-and-tools/usb-to-uart-bridge-vcp-drivers
```

For CH340 / CH341 devices, use the official WCH driver package or a driver supplied by the board manufacturer.

> **Important**
>
> The browser installer can only connect to serial devices that are already detected by the operating system.
> If there is no COM / serial port, Web Serial cannot open the Hub.

After installing a driver, reconnect the USB cable and verify that a COM port appears before continuing.

## Development / Local BIN installation

During development, use the **Local BIN file** mode in the installer.

Build the correct firmware for the hardware first.

### M5Stack Basic

```powershell
.\build-merged.ps1 -Environment m5stack-basic
```

### Generic ESP32 DevKit

```powershell
.\build-merged.ps1 -Environment esp32dev
```

Or build both:

```powershell
.\build-all-merged.ps1
```

The generated firmware files are written to:

```text
dist/firmware/
```

Example:

```text
dist/firmware/
├── DCCExpressHub-M5Stack-Basic-v0.1.0-alpha.6-merged.bin
└── DCCExpressHub-ESP32-DevKit-v0.1.0-alpha.6-merged.bin
```

In the Web Installer:

1. Open **Local BIN file**.
2. Select the correct hardware-specific merged firmware.
3. Start the installation.
4. Select the ESP32 USB serial device when the browser asks for it.

The merged firmware is a complete factory image and is flashed from:

```text
0x000000
```

The installer handles the flash address automatically.

> **Important**
>
> A complete merged/factory flash may erase NVS configuration and stored Hub data.
> Export a backup before reflashing an already configured Hub.

# First configuration

After flashing, stay on the Installer page and use the serial configurator.

Click:

```text
Connect Hub
```

The browser opens the USB serial connection at:

```text
115200 baud
```

The installer can then configure the Hub even when Wi-Fi is not working.

---

## Hub network

Configure:

- Wi-Fi SSID
- Wi-Fi password
- DHCP or static IPv4 settings
- Hub hostname
- HTTP / WebSocket port

### Hub hostname

Enter only the hostname:

```text
dccexpresshub
```

Do **not** enter:

```text
dccexpresshub.local
```

The Hub automatically publishes the hostname through mDNS.

With:

```text
dccexpresshub
```

the normal browser address becomes:

```text
http://dccexpresshub.local
```

If a custom HTTP port is configured, for example `8080`:

```text
http://dccexpresshub.local:8080
```

---

# DCC-EX / EX-CSB1 configuration

The command-station address is different from the Hub hostname field.

For the EX-CSB1 / DCC-EX host, enter the **complete address** used to reach the command station.

For example:

```text
dccex.local
```

or an IPv4 address:

```text
192.168.1.143
```

Default DCC-EX TCP port:

```text
2560
```

So the important distinction is:

```text
Hub hostname:
dccexpresshub
        │
        └── becomes dccexpresshub.local


DCC-EX host:
dccex.local
        │
        └── full address is entered here
```

Use **Test command center** before saving to verify that:

1. the host resolves,
2. TCP connection succeeds,
3. a real DCC-EX response is received.

After saving the configuration, restart the Hub when requested.

On a new installation there may be no locomotives configured yet.

You can either:

## Restore an existing installation

Open:

```text
Export / Import
```

and import a previous DCCExpressHub backup.

A complete backup can contain:

- layout,
- locomotives,
- locomotive images,
- signal logic,
- device configuration.

## Start a new layout

A practical setup order is:

1. Add locomotives in **Locomotive editor**.
2. Draw the track plan in **Layout editor**.
3. Configure turnouts and accessories.
4. Configure signals.
5. Add sensors / occupancy feedback.
6. Configure external devices.
7. Add signal logic and automation.
8. Test the layout in runtime mode.
9. Export a backup.

---

# Backup and restore

Use:

```text
Home
→ Export / Import
```

The backup system is intended to move or restore the user configuration as one JSON file.

Before firmware experiments, factory flashing or major layout changes, creating a backup is strongly recommended.

# Web UI development mode

The frontend is React + Mantine + TypeScript and uses Vite during development.

The production UI runs from the Hub, but during frontend development Vite can proxy requests to a real Hub.

Default development URL:

```text
http://localhost:5174
```

---

## Development against a real Hub

Install frontend dependencies once:

```powershell
cd web-ui
npm install
```

Set the Hub address:

```powershell
$env:DCCEXPRESS_DEVICE_URL="http://dccexpresshub.local"
```

Then start Vite:

```powershell
npm run dev
```

Open:

```text
http://localhost:5174
```

Vite proxies the Hub endpoints, including:

```text
/api
/images
/upload
/delete
/list
/fsinfo
/ws
```

to the configured device.

This allows editing the React UI with hot reload while the real ESP32 / M5Stack continues to provide the backend and DCC-EX connection.

An IP address can also be used:

```powershell
$env:DCCEXPRESS_DEVICE_URL="http://192.168.1.132"
npm run dev
```

# Development without an ESP32

The repository also contains a Node.js mock backend for frontend development.

Terminal 1:

```powershell
cd web-ui
npm run mock
```

Terminal 2:

```powershell
cd web-ui
npm run dev:mock
```

Then open:

```text
http://localhost:5174
```

In mock mode Vite uses:

```text
http://127.0.0.1:3001
```

as the development backend.

This is useful when working on:

- UI layout,
- dialogs,
- editor behavior,
- frontend state,
- API integration,
- WebSocket handling,

without repeatedly flashing an ESP32.
